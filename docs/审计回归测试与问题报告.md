## 4. 确认问题与修复前证据（历史）

### R-01｜F17：OIDC 本地状态缺少有效过期时间仍被使用

- **状态：未修复，3 个失败测试保留。建议优先级 P2。**
- 位置：`web/src/utils/auth.js` 的 `getCode()`。
- 测试：`web/tests/audit-auth.test.mjs` 中 missing/malformed/trailing-junk expiry 三个用例。
- 前置条件：localStorage 有 `oidc_code=stale-state`，过期字段缺失、为 `NaN`，或为 `<未来毫秒时间戳>garbage`。
- 复现命令：`node --test web/tests/audit-auth.test.mjs`。
- **期望：** 返回 null，清除 code 和 expiry，不重新轮询无效本地状态。
- **实际：** 返回 `stale-state`，断言 `actual 'stale-state' / expected null`；命令退出 1。
- 原因：`if (expiry && now > parseInt(expiry))` 只判断“有值且解析后已过期”。缺值跳过，NaN 比较为 false，parseInt 接受尾随垃圾。
- 影响：失效/损坏的本地状态可能持续进入登录轮询流程，登录页面恢复行为不可靠。
- **影响限制：** 这不是已证明的服务端认证绕过；服务端状态有独立 TTL 与原子消费。测试不声称获得账户访问权。
- 修复建议：严格验证正整数毫秒时间戳并检查到期（包含等于当前时刻）；无效时同时清除两个字段。修复后保持这 3 个负面用例。
- 证据：`/tmp/rustdesk-audit-regression-final/web-auth.log`，结构化证据中的 `web_auth_failures`。

### R-02｜F07/F20：heartbeat 数据库更新失败仍返回成功

- **状态：未修复，失败测试保留。建议优先级 P2。**
- 位置：`api/http/controller/api/index.go` 的 `Index.Heartbeat`，忽略 `PeerService.Update` 返回值。
- 测试：`api/http/controller/api/telemetry_failure_test.go:TestAuditF07HeartbeatReportsDatabaseFailure`。
- 前置：临时 SQLite 中设备 ID/UUID/owner 与认证会话一致，最后在线时间为一小时前，确保进入更新分支。
- 故障注入：`CREATE TRIGGER reject_heartbeat BEFORE UPDATE ON peers BEGIN SELECT RAISE(ABORT,'injected heartbeat failure'); END`。
- 复现命令：`cd api && go test -count=1 -race -run TestAuditF07HeartbeatReportsDatabaseFailure -v ./http/controller/api`。
- **期望：** 更新失败返回受控 5xx，不将 DB 错误文本暴露给客户端；不得回应成功。
- **实际：** `HTTP 200 {}`，数据库 LastOnlineTime 保持原值。测试先确认故障注入生效，再断言响应，排除“根本没有触发写入”的误判。
- 完整错误：`database write failed but HTTP 200 acknowledged success: {}`。
- 影响：客户端/监控误以为心跳持久化成功，设备在线状态可能陈旧，错误被掩盖。
- **影响限制：** 所有 ID/UUID/owner 匹配后才进入测试；这不是新的越权漏洞证据。
- 修复建议：检查 Update 错误，记录不含秘密的运维日志，返回通用错误状态；补正常心跳、限频不写以及 DB 失败用例。
