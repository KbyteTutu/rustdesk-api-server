# 功能测试与验收矩阵

## 1. 验证范围与结论

本次针对 RustDesk API Server 的 Go API、Vue 管理端、Rust hbbs/hbbr 构造并执行分层测试。新增测试运行真实 Gin 路由、校验器、鉴权中间件、业务服务和临时 SQLite 数据库，不访问生产数据库，不依赖生产账号。

**自动化回归全部通过，但不代表所有产品功能已经端到端验收。** 外部身份服务、真实桌面客户端、浏览器页面交互、网络穿透和远控媒体链路等仍有未验证项，见第 5 节。

本次没有修改生产业务逻辑，也没有添加依赖；保留工作区已有修改。新增测试和已有回归共同运行。

## 4. 可重复执行

### Go

```bash
cd api
go test -mod=readonly -race -count=1 ./...
go test -mod=readonly -race -count=1 -coverpkg=./... -coverprofile=/tmp/rustdesk-go.cover ./...
go tool cover -func=/tmp/rustdesk-go.cover
go vet -mod=readonly ./...
go build -mod=readonly ./...
```

快速跑本次 HTTP 集成测试：

```bash
cd api
go test -mod=readonly ./http/router -run TestFunctional -count=1 -v
```

测试共享应用全局对象，因此 fixture 恢复全局状态，**不得加 `t.Parallel()`**。每个 fixture 使用独立临时 SQLite，结束后自动清理。

### 前端

```bash
cd web
npm ci
npm test
npm run build
```

本次已执行 `npm test` 和 `npm run build`，使用工作区现有依赖。`npm ci` 是干净环境的安装步骤；本次未重新执行。已把 `npm test` 接入 `.github/workflows/verify.yml` 的前端 CI job；此处不声称远程 CI 已运行。

### Rust

有 Rust 工具链时：

```bash
cargo test --locked
```

本机使用现有本地工具链镜像及离线缓存执行成功：

```bash
docker run --rm --network none \
  -v "$PWD":/src \
  -v /tmp/rustdesk-audit-cargo:/usr/local/cargo-cache \
  -e CARGO_HOME=/usr/local/cargo-cache -w /src \
  rustdesk-audit-toolchain:20261114 cargo test --locked --offline
```

上述镜像与缓存路径是本机环境，不是仓库自带依赖。Rust 编译仍有 unused/dead-code 警告，且 nom 5.1.2 有未来版本兼容性警告；本次未修改这些生产代码或升级依赖。

### 进程级冒烟

需要 Docker、Go 和已构建的 `target/debug/hbbs` / `target/debug/hbbr`。脚本自行创建隔离环境并清理；不会连接生产控制 socket。

```bash
RUSTDESK_SMOKE_IMAGE=rustdesk-audit-runtime:20261114 \
  python3 scripts/audit-smoke.py
```

本机镜像与默认 `alpine:3.21` 不同；默认镜像也必须预先存在。测试 Rust 核心逻辑和启动进程不能代替远程桌面媒体链路验证。
