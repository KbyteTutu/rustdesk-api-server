## 3. 预修复方案（按实证严重度排序）

> 原则（项目约束）：不留兼容层、不做迁移、直接删过时实现；最简实现；成熟库优先；信息安全优先于性能。以下每项给出修复位置与验收标准（= 对应实证测试的反转）。

### 批次 A：立即修复（P0）

**A1. KeyExchange 防崩溃（P0-1）**
- `src/rendezvous_server.rs:628-630`：长度检查后 `try_into().ok_or`，返回协议错误并**断开连接**而非 unwrap；已存在的 `ex.keys.len() != 2` 检查保留。
- 验收：rust-runtime.py 两条畸形消息探针后 hbbs 存活且返回错误响应（exit 不为 -6）。
- 附带：删除 `:625/:630` 对 `bytes`、`their_pk`、对称密钥的 debug 打印（密钥材料禁止入日志）。

**A2. MUST_LOGIN 密钥缺失 fail-close（P0-2）**
- `src/rendezvous_server.rs:1273` 控制命令开启 must-login 时校验 `jwt::SECRET` 非空，否则拒绝启用并告警；`handle_punch_hole_request` 分支改为 `else if !jwt::SECRET.is_empty() { verify } else { 拒绝 }`。

- 附带：删除 `src/jwt.rs:18` 的 `println!("secret...")`。

**A3. 控制口与命令接口的权限边界（P0-3/P0-4）**

- 验收：非管理员 token 调 sendCmd 返回 403；无握手控制连接无法执行命令。
- WS/HTTP 入口 `X-Real-IP` 信任：仅在显式配置的反向代理 CIDR 内生效，否则保留 socket 地址。

**A4. 代理信任与封禁一致性（P0-5）**
